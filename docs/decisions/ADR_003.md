# Jurisdiction scope: GDPR-primary, jurisdiction-tagged detectors

## Context and Problem Statement

The tool is positioned GDPR/EU-first (EDPB 01/2025, ENISA, GDPR Art. 4(5)), yet its built-in
detectors skew US: `SSN` (US format, on by default) and the opt-in `NPI` / `DEA` / `VIN`
(`--detectors phi`, [#42](https://github.com/qte77/pseudonymize-text/issues/42)) are all US,
while `email` / `phone` / `IBAN` / `CC` are international and there are **no** EU national-ID
detectors. Docs referred to these identifiers inconsistently — sometimes jurisdiction-tagged,
sometimes not — which drifts and makes the EU framing look at odds with the concrete coverage.

## Decision Drivers

* The GDPR "personal data" frame is the product positioning and stays primary.
* Real corpora are multi-jurisdiction; locale-specific identifiers are legitimately useful.
* Coverage must be honest about *which* jurisdiction each detector serves.
* Docs must not drift — one source of truth, referenced rather than re-listed.

## Considered Options

* **A. Jurisdiction-tagged; US supported + EU planned** (this ADR).
* **B. Drop the built-in US-specific detectors**; push all locale IDs to `terms.csv`.
* **C. Leave as-is** — US-skewed and untagged.

## Decision Outcome

Chosen: **A.** GDPR "personal data" stays the primary frame; every detector is **tagged by
jurisdiction**; the US set (`SSN`, `NPI`, `DEA`, `VIN`) is **kept as supported** (the opt-in PHI
three behind `--detectors phi`); EU national-ID detectors are **planned**
([#86](https://github.com/qte77/pseudonymize-text/issues/86)). This supersedes a transient
proposal to drop `DEA`: under a "US supported" principle the three US PHI detectors are
**retained and tagged `US`**, not removed ad-hoc.

### Detector coverage by jurisdiction (source of truth)

Other docs link here rather than re-listing identifiers. Tagging vocabulary: **`international`**,
**`US`**, **`EU`**.

| Jurisdiction | Detectors | Enabled |
|---|---|---|
| international | `email`, `phone`, `iban`, `cc` | on (`structured`) |
| US | `ssn` | on (`structured`) |
| US | `npi`, `dea`, `vin` | opt-in (`--detectors phi`) |
| EU | `de_steuer`, `fr_nir`, `gb_nhs`, `es_dni`, `it_cf` | opt-in (`--detectors eu`) |
| any (prose) | `name`, `org`, `loc` | opt-in (`[ner]` extra) |

### Consequences

* Good — the EU framing and the concrete coverage are reconciled honestly; the imbalance is explicit and roadmapped, not accidental.
* Good — a single coverage table kills the doc drift that motivated this ADR; other docs link here.
* Good — no working code discarded; US users keep `NPI` / `DEA` / `VIN`.
* Bad — EU coverage initially lagged international + US; [#86](https://github.com/qte77/pseudonymize-text/issues/86) has since added the first EU national-ID detectors (`--detectors eu`: DE/FR/GB/ES/IT). Locales beyond these still rely on `terms.csv`.
